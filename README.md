# Лабораторная работа: Базовые механизмы Git и платформы GitHub

## 🎯 Цель работы
Приобретение практических навыков работы с системой контроля версий Git, а также подробное ознакомление с ключевыми особенностями платформы GitHub в контексте управления проектами.

---

## 📚 Краткие теоретические сведения
Git представляет собой систему контроля версий, установленную локально на компьютере разработчика и позволяющую отслеживать изменения в коде, управлять версиями и осуществлять эффективную командную работу над проектами. Платформа GitHub, в свою очередь, выступает в роли веб-сервиса, использующего Git для хостинга репозиториев и предоставляющего удобный интерфейс для совместной разработки. 

### Основные рабочие области Git
Архитектура Git состоит из трех ключевых пространств:
1. **Working Directory (Рабочий каталог):** Локальная папка на компьютере, где вы физически изменяете файлы.
2. **Staging Area / Index (Область индексирования):** Промежуточная зона, куда собираются изменения перед отправкой в историю.
3. **Local Repository (Локальный репозиторий):** Скрытая папка `.git`, где хранятся все зафиксированные снимки состояния проекта (коммиты).

---

## 💻 Выполнение работы и практические команды

В ходе выполнения лабораторной работы в терминале были выполнены следующие шаги и команды:

### 1. Настройка параметров идентификации автора
Перед началом работы были глобально заданы имя пользователя и электронная почта для корректной привязки автора к коммитам:
```bash
git config --global user.name "abdirasulovaaziza666-wq"
git config --global user.email "aziza.abdirasulova.666@example.com"
```

### 2. Инициализация локального репозитория
Для старта отслеживания версий внутри новой папки проекта была инициализирована скрытая директория `.git`:
```bash
mkdir git-init
cd git-init
git init
```
*Результат команды:* `Initialized empty Git repository in /path/to/git-init/.git/`

### 3. Проверка текущего статуса файлов
Для мониторинга состояния рабочего каталога и выявления неотслеживаемых или измененных файлов использовалась команда:
```bash
git status
```

### 4. Добавление файлов в область предварительного индексирования (Index)
Чтобы подготовить отчет лабораторной работы к фиксации, файл был добавлен в индекс:
```bash
git add README.md
```

### 5. Сохранение изменений в историю версий (Commit)
Для создания постоянного снимка состояния и сохранения проделанной работы в истории с понятным комментарием выполнена команда:
```bash
git commit -m "Выполнение лабораторной работы: Первый коммит и документация"
```

### 6. Просмотр истории зафиксированных коммитов
Для проверки созданной контрольной точки и анализа логов разработки использовалась команда:
```bash
git log --oneline
```

### 7. Механизм ветвления (Branching)
Для реализации дополнительного функционала без риска повредить основной код, была создана новая независимая ветка, а главная ветка переименована в `main`:
```bash
# Установка имени главной ветки
git branch -M main

# Создание изолированной ветки и автоматический переход на нее
git checkout -b feature-lab-task
```

### 8. Слияние веток (Merging)
После успешного завершения работы в изолированной ветке, изменения были интегрированы обратно в основную линию проекта:
```bash
# Переключение на главную ветку
git checkout main

# Слияние изменений из дополнительной ветки
git merge feature-lab-task
```

### 9. Добавление ссылки на удаленный репозиторий GitHub
Локальный каталог был связан с созданным облачным репозиторием **git-init**:
```bash
git remote add origin https://github.com
```

### 10. Отправка локальных изменений на сервер (Push)
Синхронизация локальной истории коммитов с сервером GitHub была выполнена с помощью команды отправки данных:
```bash
git push -u origin main
```

---

## 📊 Выводы
В результате выполнения лабораторной работы были успешно освоены базовые механизмы распределенной системы контроля версий Git и веб-сервиса GitHub. Продемонстрировано уверенное владение консольным интерфейсом для инициализации локальных директорий, отслеживания статусов, индексирования файлов и поэтапного сохранения состояний разрабатываемого программного обеспечения. 

На практике была применена фундаментальная концепция ветвления, позволившая изолированно и безопасно реализовать дополнительный функционал с последующей корректной интеграцией обновленного кода в главную линию разработки. Успешно отработаны ключевые методы взаимодействия с удаленным сервером, что обеспечило надежную синхронизацию локального каталога с облачным репозиторием и надежно закрепило практические навыки, необходимые для эффективной совместной работы над проектами.
